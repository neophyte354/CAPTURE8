# iPad Photobooth App

Guides building a production-quality photobooth app for iPad: a guest taps
**Start**, sees a live mirrored preview, a 3-2-1 countdown, several shots, then a
composited photo strip they can print or take home via QR code / AirDrop. The app
must survive a whole event unattended.

## Default stack (change only if the user asks)

| Concern | Choice |
|---|---|
| UI | SwiftUI, iPadOS 17+, landscape-first |
| Camera | AVFoundation (`AVCaptureSession` + `AVCapturePhotoOutput`) |
| Compositing / filters | Core Image + `UIGraphicsImageRenderer` |
| Printing | `UIPrintInteractionController` (AirPrint; DNP/Canon Selphy etc.) |
| Sharing | `ShareLink` / AirDrop, QR code (Core Image `CIQRCodeGenerator`) to an upload URL |
| Storage | App sandbox `Documents/Sessions/<id>/` + optional Photos library save |
| Project file | XcodeGen `project.yml` (so the project can be generated from text) |

If the user wants a cross-platform or web version instead, see
"Alternatives" at the bottom before writing code.

## Workflow

1. **Clarify the event requirements** (ask only what isn't stated; otherwise use defaults):
   - Shots per session (default 3–4) and countdown seconds (default 3)
   - Output layout: 2×6" strip, 4×6" postcard, or single photo (default 4×6 with 2 strips side-by-side — standard for dye-sub printers that cut 4×6 into two 2×6)
   - Output: print, digital share, or both
   - Branding: frame PNG overlay, event name/date text, colors
   - Front camera vs. external/back camera (default: front, mirrored preview, *un*-mirrored saved photo is optional — ask)
2. **Scaffold the project** from `templates/` (see "Project layout"). Copy files,
   rename the bundle id, then run `xcodegen generate` on a Mac.
3. **Build features in this order**, testing each on a real iPad (the Simulator has no camera):
   1. Camera preview + permission handling → `references/camera.md`
   2. State machine: idle → countdown → capture ×N → review → output → idle → `references/architecture.md`
   3. Compositing into the template + filters → `references/compositing.md`
   4. Print and share → `references/printing-sharing.md`
   5. Kiosk hardening: Guided Access, idle timeout, auto-reset, disk cleanup, admin panel → `references/kiosk.md`
4. **Verify** with the checklist below before calling it done.

## Non-negotiables

- **Info.plist keys**: `NSCameraUsageDescription` (required, app crashes without it);
  `NSPhotoLibraryAddUsageDescription` if saving to Photos; `NSLocalNetworkUsageDescription`
  if talking to a local print server.
- **Never block the main thread** with `AVCaptureSession.startRunning()` — run it on a
  dedicated serial queue (the template does this).
- **Rotation**: iPad photobooths are often mounted landscape *or* portrait. Use
  `AVCaptureDevice.RotationCoordinator` (iOS 17) for both preview and capture angle,
  not deprecated `videoOrientation`.
- **Mirroring**: guests expect a mirrored preview. Decide explicitly whether the saved
  photo is mirrored too; text on shirts/signs reads backwards if it is.
- **Memory**: full-res 12 MP photos × 4 + compositing can exceed memory on older iPads.
  Downscale each shot to the template slot size before compositing
  (`StripCompositor` does this).
- **Unattended operation**: every screen must time out back to idle; no modal can be
  left open forever; no dead ends if the printer is offline or there's no network.
- **Privacy**: tell guests where photos go; provide an admin "delete all sessions" action;
  don't upload anywhere without the operator configuring it.

## Building without a Mac

This container runs Linux, so Xcode builds and on-device tests can't run here. You can
still write and review all Swift source and `project.yml`. Tell the user to run on their Mac:
```bash
brew install xcodegen
cd Photobooth && xcodegen generate && open Photobooth.xcodeproj
```
then select their iPad as the run destination (camera does not work in the Simulator).
For CI, `xcodebuild -scheme Photobooth -destination 'generic/platform=iOS' build`
on a macOS runner verifies it compiles.

## Verification checklist

- [ ] First launch shows camera permission prompt; denial shows a helpful screen with a Settings button
- [ ] Preview is upright and mirrored in all four iPad orientations you support
- [ ] Countdown is large, readable from 2 m, with optional beep/flash
- [ ] N shots captured; flash/white screen feedback per shot
- [ ] Composite matches printer paper size at 300 DPI (4×6 = 1200×1800 px)
- [ ] Print works with printer offline → shows error, returns to idle
- [ ] QR / share works offline gracefully
- [ ] Idle timeout resets to start screen; session files cleaned per retention policy
- [ ] Admin panel behind a PIN / long-press; Guided Access instructions given to operator
- [ ] 100 consecutive sessions without memory growth (Instruments → Allocations)

## Alternatives (only if the user asks)

- **Web / PWA** (no App Store, runs in Safari): `getUserMedia` + `<canvas>` compositing; printing via
  `window.print()` is unreliable for photo printers — warn the user.
- **Flutter / React Native**: use `camera` / `react-native-vision-camera`; same architecture
  and state machine apply; printing needs a native plugin.
- **DSLR tethering**: iPad can't drive a DSLR directly over USB in a sandboxed app; use the
  camera vendor's SDK over Wi‑Fi or a Mac/PC as capture server.
